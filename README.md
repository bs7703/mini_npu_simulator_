> **고정밀 MAC 연산 엔진 및 하드웨어 가속기 아키텍처 분석 시뮬레이터**  
> 본 프로젝트는 NPU(Neural Processing Unit)의 핵심인 MAC 연산을 시뮬레이션하며, 부동소수점 오차 극복, 동적 스키마 검증, 그리고 대규모 연산 최적화 분석을 제공합니다.

## ✨ 주요 특징

- **고정밀 MAC 연산**: `1e-9` Epsilon 설정을 통해 부동소수점 연산의 정밀도 확보.
- **동적 스키마 검증**: 정규표현식 기반으로 패턴명에서 $N$값을 추출하고 재귀적으로 행렬 크기를 검증.
- **라벨 정규화(Normalization)**: `normalize_label` 함수를 통해 다양한 입력 형식(`+`, `cross`, `["x"]`)을 표준화된 내부 토큰으로 매칭.
- **성능 프로파일링**: 연산 크기별 실행 시간 및 **MAC Ops** 지표 산출.
- **유연한 데이터 구조**: 모든 수치 데이터를 `float(0.0)` 형식으로 처리하여 실제 하드웨어 연산 환경 모사.

## 🛠 핵심 기술 및 수학적 원리

### 1. MAC 연산과 패턴 유사도(Similarity)의 관계
본 시뮬레이터는 MAC(Multiply-Accumulate) 연산 결과를 패턴 매칭의 핵심 척도로 사용합니다.
*   **수학적 원리**: MAC 연산($\sum Input_{i,j} \times Filter_{i,j}$)은 고차원 공간에서의 **벡터 내적(Dot Product)**과 동일합니다.
*   **유사도 해석**: 
    *   **MAC 점수 상승 ⇒ 입력 패턴과 필터 간의 공간적 유사성 증가**를 의미합니다.
    *   입력 데이터의 특징(High Value)이 필터의 가중치와 일치하는 위치에 있을수록 결과값이 커지며, 이는 필터가 정의하는 특징(Feature)이 입력에 존재함을 증명합니다.
*   **임계치 판정**: 계산된 MAC 값이 필터의 고유 기준값(Base Score)과 `1e-9` 이내로 일치할 때 해당 패턴으로 식별합니다.

### 2. Recursive Schema Validation
데이터 무결성을 위해 정규식과 재귀 알고리즘을 결합했습니다.
1.  **Context Extraction**: 패턴 키(예: `size_13_1`)에서 $N=13$을 동적으로 추출.
2.  **Recursive Check**: `dict`와 `list` 구조를 탐색하며 모든 원소가 `float`인지 확인.
3.  **Constraint Propagation**: 추출된 $N$을 하위 리스트로 전파하여 모든 행렬이 정확히 $N \times N$ 구조인지 검증합니다.

## 📊 결과 분석 리포트

### 1. 시간 복잡도 분석 (Complexity Analysis)
*   **연산 복잡도**: 단일 필터 매칭 시 $O(N^2)$의 복잡도를 가집니다. $N$이 행렬의 한 변의 길이일 때, 전체 원소 수만큼 곱셈과 덧셈이 발생합니다.
*   **전체 복잡도**: 테스트 케이스 $P$개와 필터 종류 $F$개에 대해 총 $O(P \times F \times N^2)$의 연산량이 요구됩니다.
*   **성능 추이**: $N$이 5에서 25로 5배 증가할 때, 연산량은 $N^2$에 따라 25배 증가하는 지수적 특성을 보입니다.

### 2. 실행 결과 및 실패 원인 분석 (Failure Analysis)
시뮬레이션 결과는 `SUCCESS`, `FAIL`, `UNDECIDED` 세 가지 상태로 분류됩니다.
*   **SUCCESS**: MAC 연산 결과가 특정 필터의 기준값과 일치하며, 다른 필터와 중복되지 않는 경우입니다.
*   **FAIL (Classification Error)**: 연산 결과가 존재하지만 `expected` 라벨과 일치하지 않는 경우입니다. 이는 필터 설계의 변별력이 부족할 때 발생합니다.
*   **FAIL (No Match)**: 입력 데이터의 노이즈가 심해 어떤 필터의 임계치도 넘지 못한 경우입니다. (MAC 점수 미달)
*   **UNDECIDED (Tie Detected)**: 두 개 이상의 필터가 동일한 MAC 점수를 기록한 경우입니다. 이는 필터 간 직교성(Orthogonality)이 확보되지 않았음을 의미하며, 하드웨어적으로는 더 정밀한 가중치 설계가 필요함을 시사합니다.

## 💡 대규모 연산 최적화 분석 (Scalability)

$N=1000$ 이상의 대규모 행렬 처리 시 발생하는 병목 현상과 해결 방안입니다.

1.  **Memory Wall 문제**: 1000x1000 행렬은 캐시 메모리(L1/L2)를 초과하여 DRAM 접근을 강제하므로 속도가 급격히 저하됩니다.
    *   *해결책*: **Tiling(블록화)** 기법을 통해 데이터를 캐시 크기에 맞춰 쪼개어 연산 효율을 극대화해야 합니다.
2.  **CPU vs NPU 전략**:
    *   **NPU**: 단순 반복적인 MAC 연산 및 Activation(ReLU) 처리에 집중하여 병렬성을 극대화합니다.
    *   **CPU**: 데이터 전처리, 예외 처리, NPU 스케줄링 등 복잡한 제어 로직(Control Intensive)을 담당합니다.
3.  **양자화(Quantization)**: `float64` 대신 `int8` 또는 `fp16`을 사용하면 메모리 대역폭 요구량을 줄이고 연산 속도를 2~4배 향상시킬 수 있습니다.
